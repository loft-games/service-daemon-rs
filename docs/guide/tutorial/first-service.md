# First Service

This first chapter builds a small service that prints a message every few seconds, introducing the three concepts the framework is built on: **Providers**, **Services**, and the **Daemon**.

---

## 1. Define a provider

In `service-daemon-rs`, shared configuration is usually represented as a provider type. A provider is a value the framework can construct once and inject into services that ask for it.

```rust,ignore
use service_daemon::provider;

/// A simple configuration for our heartbeat interval.
#[provider(5)]
pub struct HeartbeatInterval(pub u64);
```

> [!NOTE]
> `#[provider]` registers the type with the framework. Services still request it as `Arc<HeartbeatInterval>`; the framework owns the wrapping and caching.

## 2. Write the service

A service is an `async fn` marked with `#[service]`. It can request any provider by adding an `Arc<T>` parameter.

```rust,ignore
use service_daemon::{service, sleep, is_shutdown};
use std::sync::Arc;
use std::time::Duration;

#[service]
pub async fn heartbeat_service(interval: Arc<HeartbeatInterval>) -> anyhow::Result<()> {
    tracing::info!("Heartbeat service started with interval: {}s", interval.0);

    while !is_shutdown() {
        tracing::info!("Lub-dub...");
        sleep(Duration::from_secs(interval.0)).await;
    }
    
    tracing::info!("Heartbeat service stopped gracefully.");
    Ok(())
}
```

### Why `tracing`?
Use `tracing::info!` instead of `println!` so logs flow through the framework's non-blocking logging service.

### Why `is_shutdown()` and `sleep()`?
*   `is_shutdown()`: Returns `true` when the user presses Ctrl+C or the system is stopping. This is a non-blocking check, suitable for loop conditions.
*   `service_daemon::sleep()`: Unlike standard `tokio::time::sleep`, this version is **cancellation-aware**. It wakes up when a shutdown signal is detected, so long sleeps do not delay shutdown.

## 3. Running the Daemon

The last step is to start the framework. `ServiceDaemon::builder().build()` discovers every `#[service]`-annotated function in the binary and prepares to run them.

```rust,ignore
use service_daemon::ServiceDaemon;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    // 1. build() find all services
    let mut daemon = ServiceDaemon::builder().build();

    // 2. run() starts the engine in the background
    daemon.run().await;

    // 3. wait() blocks until Ctrl+C/SIGTERM and performs graceful shutdown
    daemon.wait().await?;

    Ok(())
}
```

---

## What happened here?

1. `heartbeat_service` was discovered through the link-time registry generated by `#[service]`.
2. The `HeartbeatInterval` provider was resolved as `Arc<HeartbeatInterval>`.
3. `is_shutdown()` and `sleep()` let the loop exit promptly when the daemon stops.
4. If a service or trigger is written as a synchronous function, the macro emits a runtime warning unless `#[allow(sync_handler)]` is present.
